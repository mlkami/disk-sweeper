# 担当: data（ゲーム、ユーザーのファイル、そのほか）

## 範囲

`digest-data.md` の全部。主に次のもの。

- ゲームのライブラリとランチャー（Steam、Riot、Epic、Minecraft のランチャーなど）
- ユーザーのフォルダ（ドキュメント、ピクチャ、ビデオ、ミュージック、デスクトップ、ダウンロード）
- システムのドライブ以外のドライブ
- どの担当にも当てはまらないもの

## 見るパターンと除外

- パターン: P4（ゲームのクライアントのキャッシュ）、P5（アンインストール済みのゲームの残り）、P8（移動で解決するもの）
- 除外: X1（ゲームの Web キャッシュとリプレイ・録画の取り違え）

## 判定のこつ

- **ユーザー資産は削除候補に入れない（原則 5）。** 写真、動画、録画、セーブデータ、作品、購入したものは、大きくても A、B、D にしない。「資産」として返す（`output.md` の分類）。
- digest の上のほうにある「入れ物」の行（ドライブのルート、`C:\Users\<名前>`、`Documents` など）は、それ自体を候補にしない。中の具体的なフォルダを挙げる。
- ゲームのクライアントのキャッシュは、ゲームのログ（`Logs`、`GameLogs` など）の日付と比べる（P4）。よく遊んでいるのに何か月も書き込みがないキャッシュは、取り残された旧キャッシュ。
- ゲームは、インストール済みか（`apps.json`、ランチャーのライブラリ）を確かめる。アンインストール済みのゲームのフォルダが残っていれば A（セーブデータがあれば B）。
- ダウンロードフォルダの古いインストーラー（`.exe`、`.msi`、`.zip` など）で、同じアプリがすでに入っているものは A 候補。ただしユーザーが置いたものなので、一覧で見せて確かめる。
- 大きくて静的なデータ（AI モデル、ゲーム、素材）で、空きのあるドライブに移せるものは P8（B）。
- 中身の分からない大きなフォルダは、直下を見て何であるかを 1 行で書く（D）。
